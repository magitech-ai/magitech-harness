# magitech-harness 0.3.0

This is a minor version bump and the release that completes the 1.0 parity
milestone. The version stays in the `0.x` range until 1.0 is declared; there is
no major bump here. PyPI publication is a separate maintainer action — these
notes describe the prepared release artifacts.

## What shipped

- **Parity fixes.** All 20 retrospective findings were fixed and proven as live
  conformance cases: one unified driver, corrected pre-step rejection,
  cancellable non-streaming calls, closed turn-end taxonomy, normalized token
  usage, CodeAct escape hardening, a turn-enclosed approval service with audit
  pair, fail-closed sandbox, real compaction with a tool-result pruner, marked
  shell truncation, child-agent policy pinning, consecutive repeat reminders,
  cooperative `TOOL_TIMEOUT`, and path confinement.
- **Tier 1 completeness.** The `fs-search-tool` (registering `glob` and `grep`)
  closed the last in-scope parity gap. The ratification's 12-plugin list is
  complete.
- **Ratified CLI/config surface.** `mth headless` is the single one-shot
  command; layered `--profile`/`--patch` overlays; two homes via `MAGITECH_HOME`
  and `MAGITECH_AGENTS_HOME`. See the
  [0.3.0 upgrade guide](../upgrade-guide/v0.3.0/cli-and-components/guide.md).
- **Proof.** A recorded-fixture conformance suite, an ACC-06 wire round-trip
  record, a documentation tree reviewed against the reference checklist, and a
  Python-native benchmark baseline with committed numbers.
- **End-to-end validation.** The installed wheels were driven as an end-user,
  and every disclosed gap from that run was fixed and re-verified. The
  [live report](../conformance/e2e-live-report.md) records the results.
- **Dependency pin.** `anima>=0.3,<0.4`, matching anima 0.3.0 and making wheel
  dependency resolution succeed.

## Clean-install proof

All three 0.3.0 wheels were built from their repositories, then installed into
a clean virtual environment with normal dependency resolution (no `--no-deps`).
Resolution picked anima 0.3.0 and the third-party dependencies, and the installed
`mth` binary served a headless JSON turn and listed the 23 installed components.
This verifies the published wheel metadata is internally consistent. Actual
publication to the package index is a separate maintainer action.

## Parity map

The fresh parity map is in [`PARITY.md`](../../PARITY.md). Every in-scope item
is DONE or PARTIAL with an accepted reason; nothing in-scope is MISSING. The
reference is frozen at the pin the implementation was built against; later
reference drift is recorded in a post-1.0 appendix.

Accepted PARTIAL rows include: pinned/diverged kernel behaviors (provider
notification timing), deferred compression and repair tooling, non-streaming
checkpointing, crash recovery, CLI title drain, and the Windows ACL /
`sandbox_policy` / escalation gaps. Parallel dispatch error aggregation was
originally a PARTIAL (PIN-01) but was re-ratified to DONE on 2026-11-19 at
Malcom's decision; it is no longer an accepted gap.

The former history-scrub requirement was superseded on 2026-11-22 by D-025:
the Python stack's Cordis / DeepSeek Harness lineage is now documented openly
(see `anima/README.md`, `anima/NOTICE` and ADR 0012), the scrub-check gate was
retired, and no history rewrite was performed. The two 2026-11-07 commit
messages remain in history by decision.

## ACC-06

The bidirectional v4 wire round-trip and recorded-fixture replay are green;
all 252 recorded reference v4 fixtures validate through the harness format
layer. A live harness→other-tooling→harness run against a built install was
not reproducible in this environment. The full record is in
[`docs/conformance/acc-06.md`](../conformance/acc-06.md).

## Phase 7 tail

Secondary systems not in the 1.0 milestone remain sequenced after this release:
storage, settings, the rest of the credential store, the remaining session-query
surface, schedule tools, plan/todo/goal, preset, identity, team, workflow, web
fetch/search, ssh, ACP/SDK, attachment, and document conversion. Items that
landed early are already covered by the conformance suite.

## Compatibility and versioning

Before 1.0, breaking changes were permitted and no compatibility guarantee was
made. From the 1.0 declaration onward, breaking changes go through the
per-release upgrade guide and the versioning discipline; a breaking change
without an upgrade-guide entry is a defect. This 0.3.0 release documents its
externally perceptible changes in the
[0.3.0 upgrade guide](../upgrade-guide/v0.3.0/cli-and-components/guide.md).

## Post-parity direction

The next horizon is session resume from any major harness, delivered through
plugin adapters over the codec-catalog seam. Log migration stays in core;
foreign formats become plugin adapters. This is post-parity work and is not
started by this release.

Unresolved questions: none.
